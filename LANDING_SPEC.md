# Landing Spec — техническая спецификация сборки лендингов

Нормативный документ для массового производства брендовых лендингов проектов.
Проверяется автоматически: `node qa-check.js <slug>` (или `--all`).
Публикация разрешена только при `0 ошибок`.

Человеческая версия правил и объяснения «почему» — в [LANDING_RULES.md](LANDING_RULES.md).

---

## 1. Модель данных

Проект — один JSON в `data/<slug>.json`. Все тексты — объекты `{en, ru}`.

### 1.1 Обязательные поля верхнего уровня

| Поле | Тип | Ограничение | Проверка |
|---|---|---|---|
| `project_slug` | string | `^[a-z0-9][a-z0-9-]{0,100}$`, совпадает с именем файла | server |
| `project_name` | `{en,ru}` | — | R1 |
| `template` | string | id из `templates/` | — |
| `languages` | string[] | ≥1, первый — язык по умолчанию (`/`), остальные — `/<lang>/` | — |
| `currency` | string | ISO-код (`OMR`,`AED`,`THB`…) | — |
| `country_code` | string | ISO-2; определяет schema.org и телефонный код | — |
| `status` | `draft` \| `live` | `draft` ⇒ `noindex` + `robots: Disallow` | — |
| `group` | string | папка в сайдбаре редактора (регион) | — |
| `canonical_url` | string | URL публикации; без него нет canonical/hreflang/sitemap | **R11 ERROR** |
| `meta_title` | `{en,ru}` | ≤65 симв. | R2 |
| `meta_description` | `{en,ru}` | ≤160 симв. | R2 |
| `_sources` | string[] | откуда взяты цены и факты | R10 |

### 1.2 Секции

| Ключ | Структура | Ограничения | Проверка |
|---|---|---|---|
| `hero` | `{image, title{en,ru}, description{en,ru}, stats[{value,label{en,ru}}]}` | title ≤8 слов; stats ≥3; `image` обязателен для `live` | R3, R5 |
| `concept` | `{title, image, paragraphs[{en,ru}], specs[{key,value}]}` | параграф ≤40 слов | — |
| `amenities` | `{title, image, items[{title,description,image}]}` | items ≥4; title ≤3 слов; описание ≤15 слов; картинки — у всех или ни у одной | R4, R6b |
| `layouts` | `[{name, price_from, image, description, specs[{key,value}]}]` | ≥2; цена с валютой; картинки — у всех или ни у одной | R4, R6, R8 |
| `floorplans` | `{title}` | переименование секции, если нет реальных планировок | — |
| `roi` | `{title, subtitle, columns[], rows[], disclaimer}` | `disclaimer` обязателен при непустых `rows` | **R9 ERROR** |
| `gallery` | `{images[]}` | ≥4 рекомендуется; рендерится слайдером | R5, R14 |
| `location` | `{title, description, image, map_embed, distances[{place,time}]}` | нужен `image` **или** `map_embed`, иначе блок скрыт | — |
| `developer` | `{name, image, description, facts[{key,value}]}` | описание ≤40 слов (иначе выше фото) | — |
| `contact` | `{phone, whatsapp, email, website, manager{name,role,photo,phone,whatsapp}}` | `manager` обязателен | R15 |
| `faq` | `{title, items[{question,answer}]}` | 5–7 вопросов; ответ ≤30 слов | R4 |

### 1.3 Контракт «шаблон ↔ генератор»

Шаблоны используют разные имена полей. Генератор обязан отдавать **все синонимы**:

| Сущность | Обязательные ключи в контексте |
|---|---|
| дистанция | `place` + `name`, `time` + `value` |
| планировка | `name`/`title`, `price_from`, `price_value` (без «от»), `tab_label`, `specs[{value,label}]`, `details_html` |
| инвест-блок | `investment_highlights[{title,text,value,label,icon}]` **и** `investment_table` |
| CTA | `cta_highlights[{text,icon}]` |
| локация | `location_visual` (готовый HTML: iframe / img / пусто) |
| контакты | `manager_card` (готовый HTML) |

При подключении **нового шаблона**: прогнать демо-проект и убедиться, что
`qa-check` не даёт `R12` (пустые слоты/контейнеры).

## 2. Движок шаблонов

| Конструкция | Поведение |
|---|---|
| `{{key}}` | текст с языковыми спанами, экранируется |
| `{{=key}}` | значение для атрибута, экранируется, без спанов |
| `{{{key}}}` | сырой HTML, не экранируется |
| `{{#key}}…{{/key}}` | цикл по массиву; непустое не-массив значение = условный блок |

**Инвариант:** циклы раскрываются **снаружи внутрь**; тело элемента рендерится
в его собственном контексте с наследованием родительского (`Object.create`).
Обратный порядок ломает вложенные циклы (`{{#specs}}` внутри `{{#floorplans}}`).

**Инвариант:** значения передаются в шаблон **сырыми** (объекты `{en,ru}`),
а не пре-рендеренными — иначе разметка спанов экранируется повторно.

## 3. Инварианты вёрстки

Обеспечиваются генератором (инъекция CSS/JS), не правятся в шаблонах.

| # | Инвариант | Реализация |
|---|---|---|
| V1 | Секция ≈ 1 экран (1280×900), максимум 1.35 | лимиты высот + раскладка карточек |
| V2 | Фон не кладётся под `<img>` | инъекция фона только в блоки без картинки + рантайм-очистка |
| V3 | Пустая картинка/iframe не оставляет пустых блоков | скрытие узла + схлопывание сеток |
| V4 | Сетка с одним видимым потомком → 1 колонка | рантайм-проход после скрытий |
| V5 | Галерея — слайдер по одному фото | flex + scroll-snap, стрелки, счётчик `n / N` |
| V6 | Медиа-блоки ограничены | концепт ≤560px, галерея ≤66vh, планировки ≤480px, застройщик ≤460px |
| V7 | Длинный текст рядом с фото — в рамке той же высоты | карточка с `max-height` = высоте фото |
| V8 | Карточки: 3 в ряд (≥1100px), 2 (≥900px), 1 (моб.) | media-queries |
| V9 | Контакты отделены от футера | разделитель + компактный футер |
| V10 | Нет горизонтального скролла на 375px | проверяется вручную/скриптом |
| V11 | Контент героя никогда не обрезается и не уходит под шапку | `height:auto; min-height:100svh` + рантайм-подгон размера H1 (пол 32px) + `--header-h` |
| V12 | Меню не переносится на вторую строку | `white-space:nowrap` + рантайм-детект переполнения → сворачивание в бургер |

**Про V11–V12.** Шаблоны задают герою жёсткие `height:100vh` и размер заголовка
через `clamp(...,10vw,...)` — без учёта **длины заголовка** и **высоты окна**.
Длинный заголовок на невысоком экране обрезается сверху и выглядит как «наезд»
шапки. Лечится не подбором размеров под конкретный ленд, а рантайм-подгоном:
блок замеряет свободную высоту и уменьшает H1 шагами по 6% до 32px, дальше
герой растёт и прокручивается. Пересчитывается на `resize`, `orientationchange`
и после загрузки шрифтов.

**Важно:** `overflow` героя не трогаем — шаблоны намеренно увеличивают фон
(параллакс) и полагаются на обрезку. Снятие `overflow:hidden` даёт
горизонтальный скролл.

## 4. Правила QA (машинные)

| ID | Уровень | Условие |
|---|---|---|
| R1 | ERROR | не заполнены все языки в любом `{en,ru}` поле |
| R2 | WARN | `meta_title` >65 или `meta_description` >160 символов |
| R3 | WARN | hero title >8 слов; `hero.stats` <3 |
| R4 | ERROR/WARN | `layouts` <2 (ERROR); FAQ <4, amenities <4 (WARN) |
| R5 | ERROR¹ | нет `hero.image`; галерея пуста/<4 (WARN) |
| R6 | ERROR¹ | картинки в секции вперемешку (часть слотов пуста) |
| R7 | ERROR¹ | файл не найден; **дубль по md5** в двух слотах; >1.2MB (WARN) |
| R8 | WARN | цена без валюты |
| R9 | ERROR | `roi.rows` без `disclaimer` |
| R10 | WARN | пустой `_sources` |
| R11 | ERROR | пустой `canonical_url` |
| R12 | ERROR | пустые слоты данных (≥2 одинаковых) или пустой контейнер цикла |
| R13 | WARN | секция перегружена текстом (превышен бюджет символов) |
| R14 | WARN | >3 фото в галерее без слайдера |
| R15 | WARN | нет `contact.manager` |

¹ для `status: draft` понижается до WARN — черновики публикуются без фото
с `noindex`.

Исключения R12: декоративные и служебные классы
(`divider|burger|backdrop|overlay|line|dot|arrow|scroll|spacer|shape|blur|glow|__bg|pattern|error|consent|check|__icon|-icon`),
необязательные слоты (`-desc`, `-subtitle`, `-note`, `badge`) → WARN.

## 5. Картинки

| Параметр | Значение |
|---|---|
| Ширина | 1600px (hero 1920px) |
| Формат | JPEG, качество ~72 |
| Размер | ≤1MB (WARN при >1.2MB) |
| Уникальность | один файл — один слот (сверка по md5) |
| Источник | материалы застройщика; из PDF — `pdfimages -j` (без текстовых оверлеев) |
| Хранение | `data/<slug>/images/`, ссылки в JSON как `images/<file>.jpg` |

Раскладка слотов: `hero`, `concept`, `location`, `am-*` (по числу удобств),
`layout-*` (по типам), `gallery-N`, `developer`.

## 6. Публикация

1. `node qa-check.js <slug>` → 0 ошибок.
2. Save в редакторе (сервер повторно прогоняет QA и возвращает отчёт).
3. Deploy → Cloudflare Pages, `<slug>.pages.dev`.
4. Проверка живой страницы **с обходом кэша** (`?fresh=…` или Cmd+Shift+R):
   секции ≈1 экран, слайдер листается, нет пустых блоков, EN и RU.
5. Боевой домен: вписать в `canonical_url`, повторить Deploy — домен
   прицепится к Pages, DNS-запись создастся, если зона в том же CF-аккаунте.

**Требования окружения:** Node ≥20 (wrangler), `CLOUDFLARE_API_TOKEN`
(Pages:Edit + Zone:DNS:Edit), `CLOUDFLARE_ACCOUNT_ID`.
`dist/` эфемерна — деплой всегда пересобирает сайт из `data/<slug>.json`.

## 7. Конвейер (30–400 лендов)

```
материалы застройщика (PDF/архив)  ─┐
                                    ├─► JSON проекта ─► qa-check ─► Save ─► Deploy
research-агент (веб) ───────────────┘        ▲                │
                                             └── правки ◄─────┘
```

- Цифры из **документов застройщика** приоритетнее веб-ресёрча.
- Черновики (`status: draft`) публикуются без фото для согласования дизайна,
  с `noindex`; перевод в `live` — только после фото и `0 ошибок` QA.
- Общие правки вносятся в генератор (действуют на все ленды), а не в данные.
