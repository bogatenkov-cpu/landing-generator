# Handoff — сетка лендингов по Оману

Документ для продолжения работы в новом чате. Актуально на 5 августа 2026, коммит `da057f8`.

## Что мы делаем

Строим сеть брендовых лендингов под конкретные ЖК (жилые проекты застройщиков) — **отдельный домен на каждый проект**, не портал. Цель — собирать брендовый поисковый трафик по названиям ЖК. Старт с Омана (14 проектов), дальше масштабирование до 300–400 лендингов.

Ключевые ограничения, заданные заказчиком:
- **Скорость — приоритет №1.** Конкурент (сеть из 310 лендингов по Таиланду) грузит страницы по 7–23 МБ; мы должны быть быстрее. Сейчас TTFB 0.17–0.20 с против их 0.41–0.46 с.
- **Никакого брендинга Tranio** на лендингах. Сеть должна выглядеть как самостоятельные сайты проектов застройщиков.
- Дизайн должен быть качественный, всё должно технически работать — потому что при 400 лендингах любая систематическая ошибка размножается.
- Правила фиксируются в документах, которые потом станут переиспользуемым скиллом для массовой сборки.

## Инфраструктура

- **Редактор** — Railway, автодеплой из `main`. Постоянный том смонтирован в `/app/data`. Тариф Hobby (оплачен). Node ≥ 20 (требование wrangler).
- **Лендинги** — Cloudflare Pages, direct upload через `node_modules/.bin/wrangler` (не через npx — ломается). Каждый лендинг живёт на `<slug>.pages.dev`, кастомный домен привязывается через CF API из поля `custom_domain`/`canonical_url`.
- Публичные GitHub-репозитории под каждый лендинг **не создаём** — от этой схемы отказались.
- Переменные окружения на Railway: `CLOUDFLARE_API_TOKEN` (права Pages:Edit + Zone:DNS:Edit), `CLOUDFLARE_ACCOUNT_ID`, `ADMIN_PASSWORD`, `ANTHROPIC_API_KEY`, `GOOGLE_DRIVE_API_KEY`.

**Требует внимания по безопасности:** токен Cloudflare был вставлен в переписку открытым текстом — его нужно ротировать в CF-дашборде и заменить значение в Railway и `.env`. Старый `GITHUB_TOKEN` остался в `.env` и в переменных Railway, он больше не нужен — его следует отозвать.

## Модель данных лендинга

Все текстовые поля — объекты вида `{"en": "...", "ru": "..."}`. Верхнеуровневые ключи:

```
project_slug, project_name, short_name, template, languages, currency,
country_code, meta_title, meta_description, canonical_url, crm_webhook,
group, status, _sources
hero      — image, title, description, stats[{value,label}]
concept   — image, title, paragraphs[], specs[{key,value}]
amenities — title, image, items[]
layouts[] — name, price_from, image, specs[{key,value}]
roi       — title, subtitle, columns[], rows[], disclaimer
gallery   — images[]
location  — image, title, description, distances[{place,time}], map_embed
developer — image, name, description, facts[{key,value}]
contact   — phone, whatsapp, email, website
catalogue — image, tags[]
sell_banner — show, image, title, subtitle
faq       — title, items[{question,answer}]
```

Пути к картинкам пишутся как `images/hero.webp` — то есть **уже на webp-вариант**, не на исходный jpg. Конвейер сам создаёт `hero.webp`, `hero-1280.webp`, `hero-800.webp`, а генератор собирает из них `srcset`.

`status: "draft"` добавляет `noindex` в мету и `Disallow` в robots.txt, а также понижает часть QA-правил до предупреждений. Ленд без реальных фотографий обязан оставаться черновиком.

## Шаблонизатор

- `{{var}}` — многоязычный текст, оборачивается в `data-lang` спаны
- `{{=var}}` — значение для атрибута, без HTML
- `{{{raw}}}` — сырая вставка HTML
- `{{#array}}…{{/array}}` — цикл

Циклы раскрываются **снаружи внутрь** — это было переписано после бага, когда `{{#specs}}` внутри `{{#floorplans}}` резолвился против контекста страницы, а не элемента. Каждый элемент рендерится в области видимости `Object.create(родительский контекст)`.

## Конвейер картинок

`node optimize-images.js <slug>` или `--all`.

Ширины 1920/1280/800, качество 76/74/72. Исходники (jpg, png, webp, avif) остаются на диске как мастер-копии. Функция `isOurVariant()` не даёт конвейеру съесть собственный вывод — без неё появлялись файлы вида `hero-1280-800.webp`.

Генератор дальше переписывает `<img>` в WebP + srcset, CSS `url()` в `image-set()` и вставляет `<link rel=preload as=image fetchpriority=high>` на герой. Шрифты грузятся неблокирующе.

Результат: герой с исходных ~714 КБ → 313 КБ на десктопе и 66 КБ на мобильном.

## Что нашлось при проверке этих трёх и было исправлено

Проверка новых лендингов вскрыла четыре системные проблемы, которые касались всей сетки, а не только новых страниц.

**Битые `<img>` без файла.** В шаблонах было 11 мест, где картинка вставлялась без проверки. Нет фото — в разметку уходит `<img src="">`, браузер запрашивает адрес страницы, получает HTML и рисует иконку ошибки. Все обёрнуты в `{{#field}}`; генератор дополнительно вырезает такие теги, QA-правило R16 ловит регрессию.

**Скрытая панель планировок в anchan-indigo.** Генератор ставил класс `floorplans__panel--active`, а CSS и JS этого шаблона используют `floorplans__plan--active`. Активная панель была `display:none`, и секция выглядела как ряд вкладок над пустотой — на трёх лендингах, включая уже опубликованный. Добавлена переменная `_active_class_plan` и рантайм-страховка, открывающая первую панель, если ни одна не видима.

**Герой тянулся в полном размере на телефон.** Герой в этих шаблонах — CSS-фон, а у фона нет `srcset`, поэтому любой девайс качал файл 1920px: 450 КБ там, где телефону нужно 88. Генератор теперь дописывает медиазапросы на тот селектор, которым шаблон реально рисует герой, и выдаёт три `preload` с теми же брейкпоинтами.

**Планировка без чертежа подставляла герой.** Одна и та же аэросъёмка появлялась во всех вкладках, подписанная как разные типы квартир. Фолбэк убран.

Дополнительно: у карточки планировки в angsana не было слота цены — цена просто исчезала из секции; теперь она идёт в строку описания. В arise-vibe цена добавлена первым пунктом списка характеристик.

## Разбор скриншота с ошибкой в футере

В одном скриншоте оказалось три дефекта, все системные.

Генератор **выдумывал телефон**: при пустом `contact.phone` подставлялся `+968 XX XXX XXXX` и выводился живой ссылкой `tel:` — посетитель жмёт и попадает в никуда. Теперь пустые контакты вырезаются на сборке вместе со строкой, иконкой и колонкой, если в ней ничего не осталось. Чистится в одном месте, потому что шаблоны раскладывают эти поля по 22 разным обёрткам.

**Адресом в футере был абзац** описания локации: `contact_address` падал на `location.description`, а футер печатает это одной строкой. Фолбэк убран — нет адреса, нет строки.

**Колонки футера резались** по `max-height: 200px` без прокрутки, поэтому длинная колонка не укорачивалась, а вываливалась поверх разделителя и копирайта. Ограничение снято.

Новое правило R17 предупреждает, когда у проекта нет ни телефона, ни email — сейчас это верно для всех 15 лендингов.

## Индексация: закрыта до покупки доменов

Решение заказчика: временные адреса не индексируем, открываем после привязки собственного домена. Все 15 лендингов отдают `noindex` и `Disallow: /` — проверено на живых страницах.

Индексация теперь **opt-in**: `isDraft()` считает открытым только явный `status: "live"`. Отсутствие поля или любое другое значение означает черновик. До этой правки `aida-oceana` был открыт для индексации именно потому, что поля у него не было вовсе.

Порядок при покупке домена: прописать домен в `custom_domain`, поменять `canonical_url` на него, поставить `status: "live"`, задеплоить — привязка домена и DNS делаются автоматически через CF API.

## Грабли, на которые уже наступили

Список стоит держать под рукой — почти каждый пункт стоил отдельного разбирательства.

Папка `dist/` внутри контейнера Railway эфемерна и стирается при рестарте, поэтому деплой обязан пересобирать страницы из JSON на постоянном томе, а не полагаться на то, что сборка сохранилась.

Wrangler запускается только как `node_modules/.bin/wrangler` и требует Node ≥ 20.

Шаблоны жёстко задавали `height: 100vh` для героя и `clamp()` для заголовка, не глядя на длину текста, — длинные названия обрезались и налезали на шапку. Заменено на `height: auto; min-height: 100svh` плюс рантайм-уменьшение шрифта с нижней границей 32px для H1 и 13px для логотипа. Попытка вылечить это через `overflow: visible` на герое даёт горизонтальный скролл, потому что шаблоны намеренно растягивают фон под параллакс — так делать нельзя.

Схлопывание навигации в бургер не срабатывало, пока детектор искал `<ul>` — в шаблоне annara ссылки лежат в div. Сейчас детект идёт по признаку «браузер уже обрезал содержимое». Приоритет при нехватке места: название проекта важнее меню.

Пустые блоки должны исчезать, а не оставлять дыры. Отдельно: `<iframe src="">` раньше считался содержимым, из-за чего оставалась пустая коробка карты.

Телефонные коды берутся из `country_code`/валюты. Тайский +66 когда-то был захардкожен и в `generate.js`, и в шаблоне annara — на оманских лендингах это выглядело плохо.

Предрендеренные значения нельзя экранировать повторно, иначе на странице видны сырые `<span data-lang>`. В шаблон передаются сырые многоязычные объекты.

zsh не делает word-splitting для `for s in $SLUGS` — нужен явный список.

И самое неприятное при проверке: браузер упорно отдаёт закешированную версию. Проверять только с `?v=…` или с `Cache-Control: no-cache`, иначе легко принять старую страницу за новую.
